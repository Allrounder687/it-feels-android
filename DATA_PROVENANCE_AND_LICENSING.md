## 1. Governance & Compliance Principles

IT Feels Music's Enterprise Product Evolution adheres to strict ethical data aggregation, licensing integrity, and user privacy principles:
1. **Zero Hallucination Policy:** Metadata, credits, and artist stories are never invented, generated by ungrounded LLMs, or fabricated. Every fact traces to a verified data source.
2. **Absolute Data Provenance:** Every field ingested from upstream providers encapsulates a `DataProvenance` record tracking provider name, original identifier, confidence level, retrieval date, and licensing constraints.
3. **Privacy by Design (On-Device Analytics):** Personal listening analytics ("Your Music DNA") and taste profile computation execute 100% on the user's local device, never broadcasting personal listening habits, skips, or timestamps to third-party cloud analytics.
4. **License Adherence:** Attribution requirements, share-alike clauses, and non-commercial restrictions of upstream providers are respected in UI rendering, network transport, and persistent storage.

## 3. Data Provenance Architecture

### 3.1 Provenance Encapsulation
In the canonical domain layer, every core entity embeds provenance tracking:

```dart
class DataProvenance {
  final String provider;          // Identifier of source provider
  final String sourceId;          // Original identifier in the provider's database
  final DateTime retrievedAt;     // Timestamp of network retrieval
  final double confidenceScore;   // Confidence factor (0.0 to 1.0)
  final String attributionText;   // Human-readable attribution string
  final String licenseType;       // Exact license identifier (e.g. "CC0-1.0")
  final Duration refreshTtl;      // Maximum valid cache lifespan
}
```

### 3.2 UI Attribution Presentation
- **Track Intelligence Sheet / Modal:** Displays an expandable "Source & Verification" section indicating whether credits were verified via MusicBrainz, JioSaavn, or local ID3 tags.
- **Artist Screen:** Features a discreet legal pill in the biography header indicating data source ("Biographical facts verified via Wikidata & MusicBrainz (CC0)").
- **Lyrics Screen:** Features a footer badge ("Synchronized lyrics courtesy of LRCLIB").

## 4. Privacy, Telemetry & User Data Sovereignty (GDPR / CCPA)

### 4.1 On-Device "Your Music DNA" Isolation
- **100% Local Event Buffer:** All listening events (tracks started, completed, skipped, liked, unliked) are stored in an encrypted/sandboxed local database (`ListeningEventBuffer`).
- **Zero Third-Party Leaks:** No listening records, duration counters, or playback timestamps are transmitted to external servers, advertisers, or third-party brokers.
- **Device-Bound Computation:** Affinity scores, exponential time decay, and temporal rhythms (e.g., Night vs Morning listener) are calculated on-device inside `MusicDnaService` using local CPU isolates.

### 4.2 Right to Erasure & Profile Reset
- Users maintain absolute ownership of their listening data.
- Under **Settings $\rightarrow$ Taste Profile & Intelligence $\rightarrow$ Reset Taste Profile**, users can wipe all listening history, affinity vectors, and recorded events with a single action.
- When an entity is hidden (e.g., via "Hide Artist" or "Hide Track"), the exclusion is persisted strictly in the user's local `SharedPreferences` database.

## 5. Addon Compliance & Legal Separation (Dual-Codebase Rule)

As mandated by the core architecture guidelines:
1. **Clean Upstream Architecture:** This codebase (`IT_Feels_Alternate`) contains zero hardcoded scraping logic for YouTube, Spotify, or unauthorized reverse-engineered endpoints.
2. **User-Installed Addons:** Any stream resolution from external video or audio platforms is dynamically delegated to user-installed Addons via the sandboxed `AddonSystemRepository`.
3. **Legal Immunity:** The core music client acts strictly as an open UI/OS host and canonical metadata federator, ensuring full legal compliance with digital platform terms and international copyright treaties.
