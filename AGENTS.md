## CRITICAL SYSTEM DIRECTIVE: PERFORMANCE & RENDER PIPELINE
- **Performance Mode Profile:** Future UI performance optimizations (e.g., stripping expensive blurs or animations) MUST be conditionally wrapped behind `ref.watch(settingsProvider).enablePerformanceMode` rather than applied globally. High-end devices must retain the full premium aesthetic (frosted glass, micro-animations, etc.) unless the user explicitly enables Performance Mode (or the system auto-detects severe stuttering).
- **Navigation and Blurs:** NEVER use `BackdropFilter` or `ImageFilter.blur` in the navigation wrappers or background containers. REQUIRED: Use opaque alpha-channel colors (e.g., `context.themeSurfaceColor.withValues(alpha: 0.7)`) for visual layering.
- **Background Animations:** NEVER use an `AnimationController` to animate a `BoxShadow` blur radius or spread. REQUIRED: For pulsing or glowing effects, you must use a static `RadialGradient` wrapped in a `ScaleTransition` to force hardware-accelerated GPU transforms.
- **Custom Painters and Math:** NEVER iterate pixel-by-pixel (e.g., `x += 1.0`) in custom painters like `WavySeekBar`. Do not flood the GC with thousands of transient `Offset` nodes. REQUIRED: Maintain a minimum step size of 4.0 (e.g., `x += 4.0`) for all wave and sine-based path generations to cut math operations by 75%.
- **Data Hydration:** NEVER execute unbounded FFI deserialization or massive data list mapping on the main UI thread. REQUIRED: Large payloads (e.g., fetching thousands of audio tracks via Isar) must be paginated or explicitly wrapped in `Isolate.run()` to prevent main-thread UI locking.
- **Execution:** If a user requests a new feature, implement the business logic without touching the files governing the `WavySeekBar`, `PulseGlowBackground`, or `MainNavigationWrapper` unless explicitly ordered to override this directive.
